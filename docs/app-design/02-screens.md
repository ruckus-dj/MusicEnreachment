# Каталог экранов и информации · v2

Все экраны ниже — предлагаемая UX-спецификация. Поля берутся из технического дизайна, а производные статусы и команды требуют будущего API-контракта. «Макет» означает представление в HTML-прототипе; «Спецификация» — подробно спроектированное, но не отдельное интерактивное представление.

## S01. Setup Manager · макет

**Цель:** подготовить работающий сервис без ручного редактирования конфигов.

Композиция: пошаговый указатель сверху; слева форма текущего шага, справа объяснение последствий; снизу «Назад / Продолжить». До окончания нельзя попасть в обычную обработку, но диагностическая информация доступна.

1. **Среда:** OS/архитектура, статус БД read-only, persistent tools-directory, проверка записи. Прямое пояснение «Путь внутри сервера/контейнера, не на этом компьютере».
2. **Инструменты:** оператор выбирает одну версию FFmpeg package и одну версию `fpcalc`; по строкам показаны выбранная версия, источник, стадия установки, проверка опубликованной upstream checksum/signature при наличии, `--version` и ошибка. После валидного tools-directory Setup скачивает и активирует только выбранные версии. Повторить можно только неуспешную подготовку; update/rollback здесь нет. Прогресс без фиктивных процентов.
3. **Публикация:** абсолютный пустой output-path, проверка прав/коллизий с tools-directory, выбор «Исходный формат»/«MKA (remux, без перекодирования)».
4. **Метаданные и итог:** MusicBrainz public/self-hosted + URL в self-hosted режиме и обязательная успешная проверка соединения, приоритет MusicBrainz, LRCLIB; источник optional; итог всех путей, read-only, кнопка завершения.

Состояния: путь не существует/нет записи/нет совместимого готового бинарника для платформы/ошибка download/нет рабочей версии. Ошибка одного инструмента не теряет введённые пути. Нельзя показывать успешное окончание, если не прошла обязательная проверка. Реальную минимальную конфигурацию ещё нужно утвердить.

## S02. Входящие альбомы · макет

**Вопрос экрана:** что сгруппировано из входных файлов, что прошло автоматикой и что осталось разобрать?

- Компактная схема потока и таблица групп: число уникальных файлов, назначено/всего позиций, свободные файлы, опубликованная часть, причина и режим.
- Строка: обложка-заглушка/название, артисты, издание или исходный путь, причина, объём затронутых треков, доступность источника, следующая команда.
- Причины: неоднозначное совпадение; нет кандидатов; нет совместимого аудио; техническая проблема; провайдер недоступен; публикация не завершена; доступно улучшение (если нужно ручное решение).
- Поиск, фильтры источника и причины, сортировка по блокирующим проблемам. Список не пересортировывается под курсором при фоновом обновлении: обновление отдельной строкой «Есть новые данные».
- «Открыть» ведёт к назначениям группы. «Запустить обработку · демо» демонстрирует автоматическую публикацию полностью уверенной группы, не подтверждает неуверенные назначения.
- Массовые действия допустимы только для однородных безопасных операций; не проектируем массовое подтверждение неоднозначных match одним кликом.

Пустая очередь, отсутствие источников, поиск без результатов — три разные пустые композиции. Группировка по релизу производная; провайдерные ошибки не записываются в технические `media_variant.problem_flags`.

## S03. Сопоставление · макет

**Вопрос:** какие входные файлы соответствуют позициям выбранного издания либо локального сборника?

Три рабочие области: слева текстовый поиск releases и кандидаты; в центре трек-лист выбранного релиза; справа свободные входные файлы. Уверенные назначения заполнены. Файлы перетаскиваются на строки либо назначаются через «выбрать файл → назначить». Ниже инспектор тегов/evidence выбранной строки; закреплённый итог показывает выбранные позиции, пустые позиции и остающиеся входящие файлы.

- Кандидат: title, артисты в порядке, дата издания, страна, label/catalog number, формат носителя, число носителей и позиций, disambiguation, MBID/ссылка, дата кэша.
- Доказательства **по позиции**: raw/normalized значения, длительность и Δ, fingerprint/MBID и причины конфликтов. Будущий backend предоставляет confidence, веса и вклады; в макете числовая формула не выдумывается, fixture-verdict явно подписан.
- Сравнение: локальное поле → предлагаемое значение; выбор полей для копирования. Сохраняем возможность подтвердить связь без перезаписи ручного названия.
- Позиции: исходный файл, current track, target medium/position/track_number, title, duration delta. Видны пропуски и несовместимость; разные издания с тем же recording не сливаются.
- Команды: текстовый поиск, выбор кандидата, назначить/снять/заменить файл, выбрать публикуемые позиции, preview. Drop на занятую строку требует подтверждения. Повторное использование одного файла допускается явно, не ломая M:N.
- В режиме локального сборника центральные позиции локальные. «Найти recording» ищет композицию в других альбомах, сохраняя собственные ALBUM/ALBUMARTIST/номера сборника.

У каждого кандидата отдельный черновик; переходы не переносят назначения на чужой track-list. Частичная публикация разрешена: пустые позиции и неразмеченные файлы не препятствуют публикации выбранных доступных позиций. Недоступный провайдер оставляет ручную ветку. Конфликт версии требует обновить план.

## S04. Медиатека · макет

**Цель:** найти локальную сущность и увидеть готовность конкретного издания.

- Виды **«Артисты / Все альбомы / Все треки»**. Артисты показаны компактными карточками, альбомы и треки — плотными таблицами. Все сущности в демонстрационной выборке открываются, это не декоративные строки.
- Строка релиза: название, упорядоченные артисты, дата/страна/label/catalog number, позиции `доступно / всего`, публикация `опубликовано / всего`, provider-link либо «Вручную», актуальные проблемы.
- Поиск по названию/артисту/каталогу (по соответствующему виду), фильтр «все / опубликовано / не опубликовано». В продукте дополняется фильтрами сопоставления/источника/проблем и MBID. Сохранённые представления не обещаем.
- «Создать вручную», открыть релиз или артиста. Разные издания не объединены в одну строку без явного раскрытия.
- Empty: добавить источник или создать вручную; нет публикаций не означает пустую медиатеку.

## S05. Релиз · плотный макет

**Шапка:** выбранная обложка, title, упорядоченные артисты, release date и отдельно original date, country, label, catalog number, тип/уточнение, provider-связь. Не показывать отсутствующее значение нулём или фальшивой датой.

Компактная шапка 64 px с обложкой и встроенными счётчиками, без большого hero. Сразу под ней таблица, затем сравнение тегов. Основная команда «План публикации», не «Play». Полные вторичные формы artwork/lyrics по-прежнему спроектированы ниже, но не являются новыми интерактивными вкладками v2.

### Треки

Группировка по носителям, в том числе named medium. Колонки: отображаемый номер (включая A1/DVD1-3), название, артисты если отличаются, длительность, выбранный формат/качество, количество вариантов, выбранный текст, текущая публикация, проблемы. Отключённые позиции явно обозначены. Переход открывает **позицию**, не общий recording.

### Метаданные

Название, ordered artist credits, release/original date, primary/secondary types, country, status, packaging, barcode, label, catalog number, disambiguation, genres/tags/extra_tags. Для сравнения: поле / исходник / провайдер / локально / сейчас в публикации. Есть выбор файла, scope и только отличия. `metadata_version` не представляется историей; опубликованная колонка не подменяется локальными значениями. Поля production-редактора остаются предложением, не все редактируются в макете.

### Обложка

Один выбранный кандидат. Галерея: изображение, front/back/booklet/other, размеры, MIME, размер файла, происхождение release/release_group/embedded/manual, источник, digital/scan/unknown, score, дата. Предупреждение при выборе обложки release_group вместо точного издания. «Выбрать», «Без обложки», «Обновить кандидатов»; ручная загрузка отдельно согласуется.

### Публикация

Текущая directory_path, artwork/version, время публикации, треки по путям и версиям. Отдельно незавершённая попытка и её фаза. «Данные изменились» отличать от «Ошибка публикации». Команды preview, переорганизация, удалить managed-копию через диалог. Не удалять запись медиатеки этой командой.

## S06. Позиция трека · макет

Breadcrumb: релиз → носитель → отображаемый номер. Title override показан как «Название в этом релизе», recording.title как «Название композиции». Это предотвращает случайную правку всех изданий.

- **Источники:** radio на единственный выбранный вариант; codec/container,
  lossless, bitrate, sample rate, bit depth, channels, duration, size, quality
  score + policy version, доступные locations, compatibility и decision method.
  Matching confidence показывается у кандидатов, но не копируется в confirmed
  source link. Текущий опубликованный snapshot отдельным блоком. Вариант без
  доступной location или несовместимый вариант не выбирается.
- **Метаданные:** medium number/title/format, position, display number, overrides, extra tags, enabled. Общий recording редактируется отдельно с перечнем других затрагиваемых позиций и подтверждением области.
- **Текст:** несколько документов и языков от LRCLIB; plain/synced, expected duration, compatibility exact/probable/manual, источник и дата, preview текста/LRC. Выбрать **один** документ для этой позиции или «Без текста». Не называем plain-текст синхронизированным.
- **Публикация:** путь, codec/container, snapshot качества, selected lyrics, опубликованная/ожидаемая версия, время, pending attempt и ошибка. Нет аудиоплеера в первой концепции.

## S07. Артист · макет; общий recording · спецификация

Артист: компактная шапка, релизы раскрываемыми блоками, плотные таблицы треков. Одновременно можно раскрыть несколько альбомов. Доступны отдельная страница альбома и сравнение тегов артиста/альбома в контексте конкретного файла. В полном продукте: name, disambiguation, genres/tags и provider links с automatic/manual decision method. Confidence принадлежит кандидатам, а не confirmed links. Не добавляем биографию, подписчиков и фото, которых нет в модели.

Recording: title, упорядоченные артисты, duration, disambiguation, explicit (включая неизвестно), ISRCs, genres/tags, provider-link, все позиции использования, связанные документы lyrics. Общая правка предваряется «Затронет N позиций в M релизах». Artist sync/full discography отложены до проработки.

## S08. Ручное создание · спецификация

Форма по секциям: релиз → артисты с изменяемым порядком → носители → позиции → назначение source variants → assets. Можно начать с выделенных файлов и скопировать теги, но оператор видит conflicts и редактирует результат. Для повторяющейся композиции можно использовать существующий recording, не обязательно создавать дубликат.

Работа с неполным локальным релизом разрешена пользователем. Кнопка «Создать релиз» не публикует; результат открывается на S05. В v2 локальный сборник уже присутствует как входная группа и поддерживает назначения и поиск recordings; произвольная форма создания с нуля остаётся спецификацией.

## S09. Источники · макет

Карточки/строки корней: display name, configured server path, enabled,
доступность, processing mode, время последнего успешного scan, количество
наблюдаемых путей и уникальных вариантов (раздельно). Политика read-only видна
всегда.

- «Добавить источник»: имя, серверный абсолютный путь, проверка чтения, enabled. Удаление исходников после успеха выключено и вынесено в опасные настройки.
- «Сканировать» показывает текущую задачу, не фальшивое мгновенное обновление каталога.
- Для отключённого диска: last observed, проблема, «Проверить доступность». Отключить сканирование ≠ удалить файлы.
- Удаление корня из настроек требует будущего определения судьбы inventory-связей; не использовать неопределённое «Удалить всё».

## S10. Корень и инспектор варианта · спецификация

Корень: путь, доступность, processing mode, последняя успешная проверка, дерево
относительных путей или плоский фильтруемый список; exact path/size/mtime,
техническая проблема и число использований. Отсутствующий после успешного scan
путь не показывается как `missing`: его location удалена.

Вариант: все фактические `source_location` с root/relative path и временем
наблюдения; nullable SHA-256 и признак cached variant без locations;
codec/profile/container, streams, channels/layout, sample rate/format/bits,
bitrate, duration/size; observed_tags как массивы; раскрываемый ffprobe JSON;
fingerprint status/algorithm/duration/fpcalc version/time, сырой fingerprint
только в техническом disclosure.

«Используется в»: все track_source-связи с релизом/позицией/recording
MBID/selected/compatible/decision method. Confidence показывается отдельно у
текущих кандидатов. Несколько locations одного SHA-256 не выдаются за отдельные
улучшения качества. Variant с digest сохраняется как кэш без locations; orphan
variant без digest очищается автоматически.

## S11. Публикации · макет

Два смысловых блока: действующие managed-копии и требующие внимания изменения. Список: релиз/издание, output directory, `N/M` tracks, актуальность версии, обложка/тексты, pending/error. Фильтры: актуальные/изменились/частичные/ошибки.

Текущее опубликованное состояние отдельно от намерения: «Опубликовано MP3» не меняется на FLAC при выборе нового source до завершения операции. Для snapshot без исходника не показываем ложную ошибку managed-файла.

## S12. План публикации / переорганизации · макет

План: корневая директория, режим формата, число создаваемых/заменяемых/перемещаемых файлов, без изменений, блокеры/предупреждения. Таблица: позиция → текущий путь/формат → целевой путь/формат → действие → причина. Assets релиза и bundles треков разделены.

Перед подтверждением: scope, число файлов, качество «до/после», судьба исходников, коллизии, доступность целевого каталога. Изменение входных версий делает план устаревшим и требует пересчёта. Кнопка подтверждения неактивна при блокерах выбранной области.

Выбор производится по позициям. Можно публиковать 8 из 10 либо 1 из 10; пустые позиции пропускаются, их существующие копии сохраняются. Невключённые файлы остаются во входящих. Уже актуальные bundles помечены «Без изменений», повторная запись не запускается.

Для явного downgrade отдельный checkbox «Понижение качества подтверждаю». Для удаления managed-копии отдельный диалог с путём и количеством, отмена стоит первой по фокусу. Исходники по умолчанию сохраняются.

## S13. Операции · макет

Только текущие jobs, ожидающие retry и незавершённые publication attempts. Колонки: объект, операция, состояние/фаза, наблюдаемый прогресс, время начала/обновления, причина ожидания/ошибки, next retry если предоставляет River. Технические сведения раскрываются.

Стадии публикации: reserved → «Подготовка»; staged → «Файлы подготовлены»; validated → «Проверено»; exposed → «Новая копия доступна»; cleaning → «Очистка временных файлов»; failed → «Требуется внимание». Фазу exposed не называем полной очисткой.

«Повторить» только для допустимого состояния, без создания дублирующей попытки; точную идемпотентность задаёт backend. Нет произвольного kill, timeline завершённых jobs или обещания истории за месяц. По завершении операция исчезает, результат проверяется на объекте.

## S14. Настройки: публикация и обработка · макет + спецификация

- Глобальный переключатель темы: системная по умолчанию, светлая, тёмная. Системный режим реагирует на изменение ОС; геометрия обеих тем одинакова.

- Output directory: текущий путь, новый путь с проверкой, предупреждение о существующих копиях.
- Формат: исходный / MKA remux. Никаких MP3 V0/transcode presets.
- Именование: правила директории релиза и имени трека, доступные переменные, пример на выбранном релизе, preview массового перемещения. Синтаксис пока предложение.
- Обработка: приоритет MusicBrainz, опциональный AcoustID, расписания сканирования/проверки инструментов и порог matching только после продуктовой проработки.
- Источники: read-only по умолчанию, опасная политика очистки отдельно по корню (предложение).
- Сохранение настроек и запуск реорганизации — разные подтверждения. Ошибки inline, несохранённые изменения заметны.

## S15. Настройки: провайдеры · спецификация

MusicBrainz: enabled, public/self-hosted, base URL, приоритет, проверить соединение, доступность, дата актуальности кэша. LRCLIB: enabled, состояние и проверка. AcoustID опционально, credentials задаются в UI, после сохранения показываются только как configured/masked и никогда не попадают в URL, toast или копируемую диагностику. Replace и clear — явные действия; сохранённый secret не возвращается frontend. Не навязываем поля credentials без окончательного контракта интеграции.

Ошибка запроса не удаляет кэш. Не показываем будущих провайдеров как доступные интеграции и не добавляем «Connect Spotify».

## S16. Настройки: инструменты · макет

Сверху persistent tools-directory + редактирование с проверкой и объяснением переноса; immutable OS/arch; время последней автоматической проверки. Она выполняется не чаще раза в 24 часа по persistent client timestamp, а ручная кнопка проверки всегда доступна.

Это единственное место управления инструментами после завершения одноразового
Setup Manager: просмотр нескольких установленных версий, установка обновления,
переключение, откат и удаление неактивной версии.

По инструменту: active version и active path, managed origin, latest compatible release из текущего ответа upstream, источник/URL read-only, факт доступной upstream checksum/signature, `--version` verification и previous installed version. Кнопки «Проверить обновления», «Установить», «Активировать», «Откатить» только в соответствующих состояниях. Установка после Setup не активирует версию автоматически. Каталог версий живёт только в памяти текущей UI-сессии.

Стадии и ошибки сохраняют предыдущую рабочую версию. Если после завершённого Setup рабочей версии больше нет, settings показывает критический alert и предлагает установить/выбрать версию здесь же, не возвращая Setup Manager. Не разрешаем произвольный download URL. FFmpeg и ffprobe показываем отдельно, даже если обновление поставляется общим пакетом.

## 17. Минимальные критерии приёмки будущего интерфейса

1. Без provider-link можно создать, изменить и опубликовать локальный релиз.
2. Оператор различает источник, позицию и managed-копию на всех экранах.
3. Совпавший recording не выбирает издание автоматически без соответствующей уверенности.
4. Один вариант можно назначить нескольким позициям; у позиции только один выбранный источник.
5. Ручная замена на худшее качество возможна и заметно предупреждена; автоматическая запрещена.
6. При недоступности источника текущая публикация не исчезает.
7. Сохранение метаданных не выдаётся за завершённую публикацию.
8. Сбой одного track bundle не делает весь релиз «не опубликованным».
9. Setup не заканчивается без рабочей обязательной инструментальной конфигурации.
10. Периодическая проверка инструментов не устанавливает их; ошибка update не активирует плохой бинарник.
11. Оператор видит конкретные target-пути до удаления/замены/перемещения.
12. Keyboard focus, подписи полей, состояния загрузки и ошибки работают без зависимости только от цвета.
13. Частичная публикация не изменяет невыбранные позиции и оставляет неразмеченные файлы во входящих.
14. Recording из чужого альбома не переименовывает локальный сборник и не меняет его порядок.
15. Артисты, все альбомы и все треки доступны как разные представления каталога.
16. Смена темы не теряет черновик назначений, системный default работает без ручного выбора.
17. Confidence объясняется evidence алгоритма, а не выдуманными frontend-весами; ручное назначение не меняет рассчитанное значение кандидата.
