# Пользовательский UX и RU/EN React-макета · 2026-11-03

## Ревизия и границы

Проверено рабочее дерево на базе `6f7bffd0`, включённое в коммит вместе с этим
отчётом, ветка `go-development`. Scope — самостоятельный `docs/app-design-react/`
и синхронизация документации. Production `frontend/`, backend, инфраструктура
сборки и канонический `original-fixtures.json` не изменены. Новый снимок жанров
отделён от канонических музыкальных fixtures.

Это последующая переработка после замечаний владельца к первой реализации,
а не объявление предыдущего UI принятым. Авторитет — `docs/design/`; визуальная
приёмка владельцем остаётся отдельной от тестов и этого отчёта.

## Изменённые поверхности

- Preview: единый компактный список и постоянный inspector вместо длинной
  таблицы с раскрытием внутри ячейки. Действие, причина, источник и выходной путь
  доступны по позиции; значения сгруппированы «Поле / Сейчас / После». Списки
  значений и значимые пробелы различимы, artwork и lyrics показаны отдельно.
- Карточка трека: видимые аудиоисточники и отдельные действия выбора источника
  публикации и просмотра другого файла. В конкретном сравнении нет повторного
  выбора позиции/файла. Поля музыкальных значений не переводятся.
- Settings: категории Общие / Папки / Инструменты / Провайдеры / Жанры.
  Проверка папки сопровождает выбор, MusicBrainz — сохранение/«Далее»; название
  действия инструмента — «Установить», активация после Setup остаётся явной.
  Убраны controls имитации занятости/ошибок и внутренние токены.
- Sources: одно действие сканирования запускает обработку, ошибки повторяются
  по шагам. Удаление источника находится в его строке; сохраняются существующие
  защиты, подтверждения и границы удаления. Сброс output не возобновляет отменённую
  очередь автоматически после задания рабочей папки.
- Назначения: drag preview, принимающая область, фиксированная зона связанных
  вариантов, видимая кнопка удаления связи, краткая обратная связь и reduced
  motion. Добавление связи не выбирает новый источник публикации автоматически.
- RU/EN: системное разрешение предпочитаемых языков с fallback English,
  сохранение явного выбора, React Aria locale, `document.lang` и title.
  Notices хранятся семантическими дескрипторами, а не переводятся обратным
  поиском русских строк. Смена языка не пересоздаёт draft.
- Жанры: полный офлайн-снимок 2 220 настоящих MBID из MusicBrainz, исходные имена
  сохранены. Все читаемые английские имена оформляются автоматически и одинаково
  используются в каталоге, выборе, preview и `GENRE`. Неизвестные старые значения
  не переименовываются вслепую. Редактор необязательных точечных переименований
  не добавлен: владелец упомянул его лишь как возможную будущую потребность.

## Автоматические проверки

Итоговый `task design:check` прошёл:

- структурная проверка канонических fixtures и 6 Node fixture-тестов;
- TypeScript;
- 296 Vitest/RTL-тестов в 58 файлах;
- Vite-сборка отдельного макета.

`git diff --check` прошёл. Application gate `task verify`, application CI и
платформенные сборки не запускались по утверждённому исключению для макета.
Порог предупреждения Vite не менялся: единый JS-chunk остаётся крупным

скорости загрузки. Mechanical detector Impeccable сообщил пять предупреждений
о `border-b-2` на tabs Settings: это стандартное подчёркивание выбранной вкладки,
не толстая акцентная граница карточки. Предупреждения не подавлялись.

## Живые проверки

В Chromium проверены десять маршрутов — library, review, artist/mira,
track/north-t1, match/north, sources, settings, setup, local, operations — в обеих
локалях на 1440/768/390 px: 60 сочетаний. В проверенных состояниях нет overflow
документа, runtime page errors и несовпадения `document.lang` с выбранным языком.
Имена музыкальных объектов и пользовательских источников, включая кириллицу,
сохраняются независимо от языка интерфейса.

Дополнительно проверены:

- inspector: высота 540 px, положение и ширина неизменны при выборе другой
  позиции; на 390 px открывается отдельная панель, Escape закрывает её и
  возвращает фокус исходной позиции;
- native mouse drag: добавление и удаление связи не меняют положение таблицы
  и высоту строки (в проверенном состоянии 112 px), не выбирают аудио автоматически;
- keyboard drag: Enter запускает перетаскивание, Tab достигает цели Northbound,
  Enter добавляет связь; Escape отменяет drag и возвращает фокус;
- альтернативное назначение выбором файла и кнопкой Add с клавиатуры, удаление
  связи, видимость выбранного radio;
- reduced motion: у drop target `transition-duration: 0s`, `animation-name: none`;
- осмотр MP3 на карточке трека не меняет выбранный FLAC-источник публикации;
- черновик названия сохраняется при RU → EN; Cancel восстанавливает сохранённое
  значение. Поиск жанров сохраняет запрос, `Alternative R&B` одинаков в RU/EN;
- staged scan автоматически даёт состояние шагов, сохранённая копия блокирует
  смену рабочей папки; повтор fingerprint и очистка копии разблокируют её,
  состояние сохраняется между Sources/Settings;
- некорректный URL MusicBrainz отклоняется при Save и не помечается проверенным;
  корректная конфигурация имеет свой fingerprint, изменение сбрасывает проверку.

При live-проверке найдены и устранены две проблемы, которые одних callbacks
не показывали: появление первого notice сдвигало всю таблицу; ref drop target
указывал на нефокусируемый wrapper и ломал keyboard drag. Добавлены регрессии
резервирования feedback и регистрации focusable drop button. Поиск по большому
каталогу проверяет точное совпадение перед страницей поджанров, сохраняя
выбранные значения вне видимой страницы.

## Ограничения

Нет настоящего скачивания, сетевого обращения к провайдерам, исполнения
инструментов или записи музыкальных файлов: источник данных макета фиксированный.
Обычные пользовательские controls не являются утверждением реализации backend.
Снимок каталога жанров может устареть; он не заменяет целевую синхронизацию
полного MusicBrainz API через настроенный governor. Автоматическое оформление
не объявляется универсальным внешним стандартом написания всех жанров.

Расчёт громкости, алгоритм и альбомный аудиоконтекст остаются отдельной задачей;
результаты не выдумываются. Не выполнялись тестирование физического touch-устройства,
скринридера, filesystem crash recovery и пользовательское исследование.
Screenshots не создавались. Успешные проверки не заменяют оценку удобства владельцем.

## Дополнение: drop-подсказка без постоянного блока

Последующее уточнение владельца, рабочее дерево на базе `c5a86994`: постоянная
34px строка «Drop an available file here» удалена. Область назначений уменьшена
со 112 до 80 px; в покое показывает связанные файлы, обычное добавление и
осмысленное пустое состояние. Подсказка появляется absolute-overlay поверх
этой же области только при активном drop target. Overlay не перехватывает
pointer events. Клавиатурная drop-кнопка остаётся зарегистрированной, но
исключена из обычного tab-порядка через React Aria `excludeFromTabOrder`.

`task design:check` прошёл повторно: 296 Vitest-тестов в 58 файлах, 6 проверок
fixtures, TypeScript и Vite build. Независимое ревью и проверка TypeScript
обнаружили несогласованные новые children в тестах и использование неподдерживаемого
`tabIndex` на React Aria Button; оба замечания исправлены без ослабления проверок.

В Chromium проверены EN mouse drag с удержанием над целью и RU keyboard drag
Enter/Tab/Enter, отмена по Escape с возвратом фокуса. В покое drop-подсказок нет;
над целью ровно одна, после drop/отмены исчезает. Измеренные положение и высота
строки до, во время и после mouse drop одинаковы (80 px). Явный выбор radio и
удаление связи доступны обычным кликом; добавление не выбирает источник за
оператора. На 1440/768/390 px нет горизонтального overflow документа; при
reduced motion переходы 0s, animation none. Production-код и канонические
fixtures не изменены. Ограничения браузерной проверки из раздела выше сохраняются.
