# План 13: финальная браузерная матрица и живой MusicBrainz

## Сравнение production и прототипа

Chromium, real backend `f8b42863` на отдельной БД
`plan13acceptance_final_20261117`, standalone React с текущего дерева.
Через штатную навигацию проверены Incoming, Library, Own catalog, Sources,
Operations и Settings: 48 состояний на каждой поверхности (RU/EN,
light/dark, 1440×900/390×844). Сравнивались видимые заголовки,
геометрия оболочки и фактическое переполнение страницы; данные прототипа
и продукта различаются. Это не pixel diff; screenshot-артефактов нет.

Прототип не переполнялся. В production на заполненном экране Operations
ширина документа на 390 px составляла 801 px в EN и 766 px в RU в обеих
темах. В остальных состояниях матрицы переполнения не обнаружено.
Причина — absolutely positioned скрытый заголовок Actions, для которого
scroll wrapper не был containing block. `ed6034bc` задаёт его именно
на wrapper. До обновления embedded binary правило проверено в Chromium
в восьми состояниях: 390 px остаётся шириной страницы, 850 px —
внутренней шириной прокручиваемой таблицы. На desktop ширина страницы
не меняется. Retry при получении фокуса видим, семантика локализованного
заголовка и raw diagnostic сохранены. Независимое ревью без замечаний,
обычный полный hook прошёл с Homebrew `libarchive` в `PKG_CONFIG_PATH`.
Те же восемь состояний повторены на собранном embedded приложении с
обеими правками: mobile document 390 px, table scroll width 850 px;
desktop document 1440 px, без изменения ширины таблицы. Retry достижим
при фокусе; Actions / Действия остаётся заголовком столбца.

## Прогон автоматического сопоставления

Временный 264-секундный FLAC — синтезированный тон, не аудио релиза.
Теги artist/album/title/date/track соответствуют публичному однотрековому
релизу Tiny Little Houses `adbd5f3a-b38c-4f9f-bc44-35938daf46e4`.
Provider ID в FLAC не задавались. Регистрация отдельного каталога выполнена
через Sources → Add source → server folder picker → Register source.
Реальные scan/analysis сформировали готовую группу с automatic authority;
сопоставление началось без ручного выбора релиза.

Проверка public mode в Settings показала healthy. Поиск артиста прошёл,
но Artist releases и родительская Match evaluation завершились ошибкой.
Один явный Retry через Operations принят и снова завершился ошибкой.
Read-only запрос к MusicBrainz с параметрами адаптера подтвердил HTTP 400:
`artists is not a valid inc parameter for the release resource`.
Без `artists` тот же browse вернул 12 релизов, в том числе целевой, с
artist credits и release group. Health lookup не проверял этот browse.
Прямой отдельный release lookup один раз вернул 503; это не меняет
доказанную причину browse 400 и не подтверждает весь lookup pipeline.

## Повтор после исправления `5fc85d8e`

Удалён только неподдерживаемый browse include, lookup не менялся.
Существующий HTTP-тест проверяет точный набор трёх includes в декодированном
query. Первоначальное тестовое утверждение ошибочно ожидало `+` после
URL-decoding; после замены на `strings.Fields` regression и полный hook прошли.
Независимое ревью не выявило проблем в production-изменении.

На gate-built binary штатный Retry операции Artist releases
`9294d802-a52e-4a1f-9bab-dd395424bfa1` завершился `provider_response_saved`.
У родительского `660d805c-a02b-4450-a9af-8b60d74b8090` Retry принят (HTTP 200),
но повторно завершился той же ошибкой: уже записанный terminal dependency
outcome сохраняется при повторе доставки того же запуска, даже если дочерний
повтор сохранил новый ответ. Retry не является новой оценкой. Поведение
recovery/authority не менялось.

В том же временном source добавлен другой синтезированный FLAC без DATE,
поэтому он образовал отдельную группу, а не вторую позицию прежней.
Штатный Scan (HTTP 200) запустил анализ и новую автоматическую оценку;
успешные evaluation/apply сохраняют результат для просмотра. Новый запуск
использовал provider cache, наполненный реальным запросом после исправления.
В группе `7209e778-0627-553f-890c-081354fab653` (automatic) браузер прочитал
10 candidate edges. Для `Every Man Knows His Plague; and You Are Mine.`
сохранённые release confidence и position confidence равны 1; показаны
факторы, вклад и `matching-rapidfuzz-v1`, без подстановки вычислений UI.
Это реальный backend, без API fixtures.

В локальном draft выбрана позиция, включён Override title и введено
`Acceptance title override 20261118`. RU → EN не вызвал API-запросов и
сохранил draft. `Preview all assignments` вернул HTTP 200, результат
содержал Manual metadata to apply и указанное название. Восемь состояний
RU/EN × light/dark × 1440×900/390×844 сохранили evidence, preview и текст
без запросов и переполнения. Confirm explicitly не нажимался, новые
MusicBrainz-позиции не публиковались. SHA-256 обоих новых тоновых исходников
и исходника сквозного Local-прогона совпал с соответствующим pre-scan hash.

## Ограничение контрольных файлов

Повторная проверка 18 ноября обнаружила, что два прежних CURRENT и три
исходника отсутствуют в пяти путях из записей `path: OK`. Родительские
каталоги существуют и пусты, их mtime — 17 ноября, 03:36:33, до текущего
прогона. Этот timestamp не устанавливает причину или инициатора удаления.
В проверенных каталогах evidence, проекта и доступных локальных копий
оригиналы не найдены. Исходные digest values также недоступны. Это новое
наблюдение, а не опровержение ранее выполненных проверок. Файлы не
пересоздавались и не заменялись новыми тонами. В текущем прогоне мутации
делались только на отдельной БД и в disposable каталоге; 8787 не затронут.

После проверки `18080` штатно возвращён на исходную БД `plan13acceptance`
(PID `56716`, `/health` HTTP 200). Отдельная БД и её исходники сохранены.
Повторное доказательство сохранности исторических файлов требует исходных
копий и digest values либо явного решения владельца принять это ограничение.
