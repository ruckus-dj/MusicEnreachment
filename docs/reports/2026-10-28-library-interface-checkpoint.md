# Каталог и ручное создание: промежуточная проверка 2026-10-28

Проверявшийся код: `e6ce4c4` с исправлением запроса каталога и прямыми
PostgreSQL regression-тестами в рабочем дереве. Это промежуточный результат,
не приёмка всего плана №13 и не подтверждение GitHub CI.

## Проверки

- Полный `task verify` после исправления SQL прошёл: backend integration,
  443 frontend-теста, 17 tools-тестов, lint, генерация и production build.
- На обновлённом Docker-стенде `http://127.0.0.1:8787` список релизов
  возвращает HTTP 200. Через форму создан один проверочный локальный релиз
  `07af51f9-53cd-4a41-a5fb-8c11c1097b1b` с новым артистом, двумя носителями
  (один пустой), позицией и независимым recording. Сохранена ручная
  длительность 83000 мс; исходники и обложка не назначались.
- Создание вернуло HTTP 201. Чтение релиза и всех трёх представлений каталога
  вернуло HTTP 200. Страницы артиста и прямой позиции открылись без alerts.
  Публикаций осталось 0; неизвестный провайдерный знаменатель остался `null`.
- При ширине 390 px документ не переполняется. Последний пункт мобильной
  навигации становится видимым при фокусе; навигация прокручивается локально.
- Скриншот выявил отдельную CSS-ошибку: `flex-basis: 16rem` становился высотой
  поиска при колонке toolbar. Добавлено мобильное переопределение flex;
  оно требует повторной визуальной проверки после обновления стенда.

## Найденный пропуск и предотвращение

Первоначально зелёные тесты проверяли артистов и provider-enrichment helper,
но не исполняли `ReadLibraryReleases`. Браузер выявил HTTP 500 из-за
незакрытого SQL-предиката. Теперь regression-тест вызывает сами методы
списка релизов и позиций на пустой и заполненной БД, включая фильтрацию,
поиск и страницы за пределами выдачи. Проверка helper не заменяет такой
контрактный тест конечного read-path.

## Ограничения

- Не подтверждён полный путь от нового источника через анализ и входящие
  до публикации и обнаружения результата в каталоге.
- Не завершено сравнение всех экранов с общим макетом в обеих темах.
- Семантика фильтра публикаций «Изменились» ожидает решения владельца;
  она не подменена ошибками, заданиями или сравнением тегов.
- Проверочный релиз является текущими данными локального стенда, а не
  fixture или демо-данными приложения. Существующие данные не изменялись.
