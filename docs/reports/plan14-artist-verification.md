# План 14: проверка ветки MusicBrainz с исполнителем

Ревизии: `1da4a303` — использование принятых ответов и целой раскладки;
`f9902e82` — проверка неизменившихся данных при повторном наблюдении записи
и обнаружение `libarchive.pc` на macOS; `f5d548ad` — обновление открытого
разбора по свежему списку изданий. Все три коммита прошли штатный
`task verify` в commit hook. Тест `f5d548ad` также проверяет, что новый
подтверждённый пустой ответ обновляет разбор без новой задачи применения.

## Повтор на сохранённых входах

На `1da4a303` повторён [офлайн-контроль утверждённого правила](plan14-approved-layout-replay.md)
с порогом `0.70`. Время одного прохода, без сети и записи назначений,
в миллисекундах:

| Вход | Отбор | Полный расчёт | Результат |
| --- | ---: | ---: | --- |
| Local «Punk-O-Мания 2» | 0,56 | 26,72 | 21/21, сумма 20,17287 |
| MusicBrainz «Жечь электричество!» | 56,98 | 395,09 | 52/52, сумма 52 |
| `7bdaad49` | 0,10 | 5,34 | 2/2, издание `19d437c3…`; правильное издание не подтверждено |
| `a1b7a6d6` | 0,01 | 0,57 | Нет полного треклиста; назначений нет |

Первые три результата воспроизводят сохранённые контрольные раскладки.
Сравнение с [T01–T03](plan14-matching-experiment.md) проверяет поведение
на том же корпусе, а не качество текущего сетевого поиска.

## Стенд и CI

На стенде для `f5d548ad` перестроен только `app`. Для «Punk-O-Мания 2» совпали снимки
группы, её состава и оценки в БД и SHA‑256 всех 21 исходных файлов.
Монтирование `/downloads` осталось только для чтения.

[CI для `1da4a303`](https://github.com/ruckus-dj/MusicEnreachment/actions/runs/45005624374):
основная проверка, Docker smoke, Windows x64, Linux arm64 и macOS x64 прошли.
macOS arm64 остановился до тестов: Homebrew установил `libarchive`, но
`pkg-config` не увидел его метаданные. На
[`f9902e82`](https://github.com/ruckus-dj/MusicEnreachment/actions/runs/45009003907)
общая проверка сначала остановилась на тесте `ManualReleasePicker`
(`Release prepared.`); повтор неудавшихся заданий завершился успешно.
[CI для `f5d548ad`](https://github.com/ruckus-dj/MusicEnreachment/actions/runs/45009576975)
и [CI для `4888cdbc`](https://github.com/ruckus-dj/MusicEnreachment/actions/runs/45010514261)
прошли полностью, включая все платформы, Docker smoke и публикацию контейнера.
На стенде после `4888cdbc` снимки группы и SHA‑256 её 21 исходника снова
совпали; `/downloads` остался только для чтения.

Перепроверка Local после восстановления MusicBrainz, передача CURRENT и
сквозная приёмка переноса не подтверждены этим прогоном.
