# Основной интерфейс: продолжение проверки 2026-10-29

Проверявшиеся ревизии: опубликованный `690d17a` и последующие frontend-правки
в рабочем дереве. Это продолжение промежуточного отчёта от 2026-10-28,
не приёмка всего плана №13.

## Код и локальная проверка

- В карточке релиза добавлено чтение сохранённых полей релиза, пустых
  носителей, ролей и упорядоченных credits, ручной длительности, независимых
  названия и идентичности recording. Отображаются исходники позиции,
  выбор, совместимость, decision method, policy version и locations.
- Canonical имя артиста показано отдельно, если отличается от credit name.
  Credits позиции видны независимо от селектора основного исполнителя;
  повторяющиеся артистические идентичности не теряют порядок и роли.
- Основная навигация приведена к согласованным шести разделам; полезная
  стартовая страница остаётся доступной через бренд.
- Итоговый локальный `task verify` прошёл: backend integration, 445
  frontend-тестов, 17 tools-тестов, lint без замечаний, генерация и build.

## CI

Прогон `40769957544` для `690d17a` завершился неуспешно: новый тест времени
публикации зафиксировал московский UTC offset, тогда как runners используют
другие часовые пояса. Backend integration прошёл на всех пяти платформах,
Compose smoke прошёл; frontend и последующие platform builds не считаются
пройденными. Container publication был пропущен.

Исправлен именно тест: проверяются исходный `datetime` и текст, рассчитанный
для локального часового пояса тестовой среды. Поведение приложения и
настройки часового пояса не менялись. Новая полная матрица CI ещё требуется.

## Дополнение: публикация на физических папках, ревизия `1140cef`

После восстановления стенда через UI создан локальный релиз «Восьмибитки»
`e98c894b-4a48-446f-83c2-0ba7acc5974f`: 12 позиций с явным назначением по
одному исходнику. Исполнители дорожек дополнены через существующий редактор
этого же релиза; новый дубликат релиза не создавался.

Первоначальный предпросмотр выявил несовместимость дополнительной Linux
проверки casefold flags с физической папкой macOS через virtiofs. По явному
решению владельца платформенные scope-проверки удалены, эмпирическое
сравнение имён пробными файлами и безопасная очистка сохранены.
Монтирования, настройки и расположение данных не менялись.

На `1140cef` предпросмотр первой позиции прошёл без блокирующих условий.
Операция публикации `2b170c1b-635c-45df-bf54-65d2c76d0e43` завершилась
`succeeded` (2026-10-29, 10:36:41 UTC). Позиция
`40879ff1-40ca-4b5b-a7d0-2a5bd007983f` появилась в списке текущих публикаций:
ALAC/M4A, output root `/var/lib/melotrove/output`.

Файл подтверждён на хосте в прежнем `test_stand/data/media-go`:
`Кис-Кис [4963eaaa-0eaa-49af-b75c-374516890f79]/Unclassified/Unknown year - Восьмибитки [e98c894b-4a48-446f-83c2-0ba7acc5974f]/01-01 - ЛБТД (8-bit).m4a`.
Все 12 исходных FLAC остаются в исходной папке. Каталог показывает
`position_count=12`, `published_position_count=1`, `available_position_count=1`,
`provider_position_count=null`: наличие исходников не подменяет публикацию.

Обнаружено отдельное ограничение приёмки: открытая карточка позиции более
120 секунд показывала `preparing (running)`, хотя операция уже завершилась.
После перехода в публикации и каталог результат доступен. Причина обновления
карточки исследуется; сквозной путь до файла/CURRENT подтверждён, но полная
UI-приёмка ещё не закрыта. Локальный gate и обычные hooks для `1140cef` прошли;
полная CI-матрица этой ревизии на момент дополнения выполняется.

Диагностика зависшего статуса выявила отсутствие completion wake-up в
`PublicationWorker`: фиксация CURRENT и terminal operation атомарна, но worker
не уведомлял подписчиков API. Подготовлена отдельная правка: shared operations
service передаётся worker, уведомление отправляется после возврата executor
как при успехе, так и при ошибке. Добавлены детерминированные worker-тесты
порядка уведомления и композиционный тест общего API subscriber. Независимое
ревью правки не выявило замечаний; gate и проверка обновления карточки на
следующей позиции ещё требуются.

## Дополнение: общий выбор папок после `add16b6`

Проверялось незакоммиченное рабочее дерево после `add16b6`: общий пикер
подключён к шести полям мастера, настроек и источников. Внешние пути доступны
только для чтения; выбор подтверждается внутри диалога. Полный `task verify`
прошёл: 464 frontend-теста, backend integration, 17 tools-тестов, lint,
генерация и build. Это локальный результат, не CI текущих изменений.

На стенде проверены отмена без изменения внешнего пути, подтверждение пути
в форме добавления источника и Enter без отправки этой формы. Отмена вложенного
пикера сохраняет открытым диалог переноса Tools. Источники и настройки при
проверке не сохранялись, перенос не запускался.

Подтверждение выбора в настройках пока не принято: браузерные запросы списка
папок задерживаются, хотя тот же API отвечает через curl. Причина исследуется;
общая приёмка плана №13 и CI незакоммиченной интеграции остаются открытыми.

Дополнительная браузерная проверка того же стенда: при viewport 390×844
пикер имеет ширину 358 px, горизонтального переполнения нет, список
прокручивается отдельно от footer. Светлая и системная тёмная темы проверены
скриншотами; смена системной темы применяется без перезагрузки. Это проверка
пикера источников, а не завершённая приёмка всех экранов плана.

Причина задержки в настройках установлена по коду: отдельный EventSource для
каждой строки операции исчерпывает пул HTTP/1-соединений браузера; подписывались
также строки `failed`. В рабочем дереве добавлен общий wake-only endpoint
`/api/operations/events` и один reference-counted поток для всех followers.
После уведомления они продолжают читать REST; polling и требования к proxy
не добавлялись. Legacy endpoint сохранён. При ревью исправлен формат SSE:
именованное событие содержит постоянное `data: {}`, иначе native EventSource
не доставляет уведомление. Повторный gate и проверка обновлённого стенда
на момент этого дополнения выполняются.

На обновлённом стенде (`index-DpxyHJ7_.js`, рабочее дерево после `add16b6`)
браузер открыл один `/api/operations/events`. Два запроса папок в диалоге
переноса Tools завершились за 29 и 10 ms вместо прежней минутной задержки.
Отмена и подтверждение закрывают только пикер; выбор `/var/lib/melotrove`
меняет черновик пути, а последующая отмена внешнего диалога не запускает
перенос. Отмена пикера output оставляет прежний путь. Оба внешних поля
read-only. Настройки и перенос при проверке не сохранялись.

Окончательный локальный прогон: 465 frontend-тестов и все backend integration,
17 tools-тестов, lint, генерация и build прошли. Независимое повторное ревью
пикера и жизненного цикла общего SSE не выявило блокирующих замечаний.
Финальный стенд (`index-C7i4Gmki.js`) повторно подтвердил выбор папки внутри
Tools без закрытия внешнего диалога; запрос папок занял 15 ms. Обычные hooks,
push и полная CI-матрица текущего коммита ещё должны завершиться; весь план №13
этим дополнением не закрывается.
