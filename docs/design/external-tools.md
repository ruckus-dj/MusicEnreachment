# Обновление внешних инструментов

## Зафиксированные требования

- Инструменты: `ffmpeg`, `ffprobe` и `fpcalc`.
- Базовый Docker-образ уже содержит эти бинарники.
- Инструменты должны работать и при локальном запуске без Docker.
- UI показывает установленную версию через `--version`, по запросу проверяет
  обновления и позволяет их установить.
- Проверка обновлений выполняется также периодически.
- Поддерживаются Linux, Windows и macOS в вариантах `amd64` и `arm64`; для
  каждого сочетания должны быть доступны совместимые готовые бинарники
  `ffmpeg`, `ffprobe` и `fpcalc` из утверждённых доверенных источников.
- Источники готовых `ffmpeg` и `ffprobe` для каждого сочетания OS и архитектуры
  фиксируются отдельно до реализации их загрузки.
- Готовый `fpcalc` берётся из GitHub Releases проекта AcoustID Chromaprint:
  https://github.com/acoustid/chromaprint/releases.
- При первом запуске Setup Manager требует выбрать persistent tools-directory.
  Этот путь можно изменить в UI настроек приложения.
- Приложение самостоятельно получает готовый совместимый выпуск инструментов;
  ручная установка бинарников оператором не требуется.

## Утверждённый lifecycle

1. Setup Manager требует persistent tools-directory, определяет OS и
   архитектуру, затем проверяет доступность совместимых готовых инструментов.
2. Для каждого инструмента приложение хранит в PostgreSQL текущую версию,
   источник, URL, digest, путь и время последней проверки.
3. Проверка обновлений получает только описание готового release из заранее
   заданного доверенного источника; произвольный URL из UI не принимается.
4. Установка скачивает готовый совместимый release в staging, проверяет digest
   и, если доступно, подпись; затем запускает `ffmpeg --version`,
   `ffprobe --version` и `fpcalc --version`, сверяя результат с ожидаемой
   версией release.
5. После успешной проверки новая версия атомарно становится активной, а прежняя
   остаётся доступной для ручного отката.
6. В Docker persistent volume хранит managed updates. Приоритет использования:
   успешно проверенная managed-версия, затем baseline из образа.
7. При первом запуске приложение автоматически подготавливает инструменты после
   выбора tools-directory. Позднее периодическая проверка только сообщает о
   новой версии; скачивание и активация выполняются по явному действию оператора
   из UI.
8. Ошибка скачивания, проверки целостности или `--version` не активирует новый
   бинарник. Сервис сохраняет предыдущую рабочую версию, а при её отсутствии
   оставляет Setup Manager незавершённым и показывает оператору критический
   alert.

## Ограничения

- Целевые платформы: Linux, Windows и macOS в вариантах `amd64` и `arm64`.
  Другие OS и архитектуры не поддерживаются.
- Для целевой платформы необходимы совместимые готовые бинарники всех трёх
  инструментов из утверждённых доверенных источников.
- Проверка `--version` подтверждает запуск и соответствие ожидаемому release,
  но не заменяет проверку digest или подписи, когда она опубликована источником.
