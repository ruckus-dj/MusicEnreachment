# Требования

## Контекст продукта

MusicEnreachment — серверное web-приложение для персональной или небольшой общей
медиатеки. Основное место развёртывания — NAS или другой постоянно работающий
локальный сервер; приложение работает с доступной серверу файловой системой, а
оператор управляет им через браузер. Web-интерфейс проектируется desktop-first и
не обязан быть mobile-first. По идее продукт близок к SoulSync, но использует
контролируемую организацию и явные ручные действия оператора.

Сервис получает файлы из локальных директорий и подключаемых дисков. Источники
по умолчанию read-only; по отдельной настройке исходный файл можно удалить
после успешной публикации.

Для каждого входящего каталога оператор выбирает обработку на месте либо через
временную копию в общем work-directory. Второй режим предназначен прежде всего
для HDD и сетевых источников при быстром локальном scratch-диске. Глобальная
настройка позволяет вычислять SHA-256 для новых и изменённых источников и
переиспользовать уже известный точный вариант; переключение не обрабатывает
существующие записи ретроактивно.

Первичный провайдер метаданных — MusicBrainz, включая self-hosted
развёртывание. Тексты запрашиваются из LRCLIB. Spotify, Apple Music, Discogs,
Deezer и другие провайдеры относятся к будущим отдельным продуктовым задачам.

Сервис ведёт управляемую папку публикаций с выбранными аудиоисточниками,
метаданными, обложками и текстами. Он создаёт, удаляет, заменяет и
переорганизует публикации; входные источники не изменяются без явно включённой
настройки удаления.

Многочасовые и крупные audio sources не исключаются из scan. CUE или ручные
границы могут назначить сегменты одного source нескольким tracks; без явной
разметки приложение не делит большой файл автоматически.

Встроенной аутентификации и авторизации нет: приложение не управляет
пользователями, сессиями, токенами, ролями или разрешениями и считает полностью
доверенным любой клиент, достигший backend. TLS, authentication и ограничение
сетевого доступа обеспечивает deployment — например, reverse proxy с
forward-auth. Bundled UI и API работают с одного origin; CORS не требуется.

Environment ограничен bootstrap-конфигурацией: PostgreSQL connection и
необязательные HTTP bind address/port. Все рабочие настройки, включая log level
и любые credentials внешних API, изменяются через UI и хранятся в PostgreSQL.
Сохранённые secrets не возвращаются через API и не попадают в логи или URL.

Каждая новая продуктовая задача должна пройти отдельную полноценную
проработку до начала реализации.
