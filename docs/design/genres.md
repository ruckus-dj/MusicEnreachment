# Каталог жанров

## Назначение и источник

Продуктовые требования к scopes и использованию жанров заданы в
[`продуктовом контракте`](./decisions.md#провайдеры-сопоставление-и-медиатека). Здесь
описаны только особенности каталога и его интеграции.

Приложение поддерживает одну общую локальную библиотеку жанров, полученную из
MusicBrainz и доступную для выбора при редактировании жанров. Источник следует
текущей конфигурации MusicBrainz приложения: публичный сервис либо настроенный
self-hosted endpoint. `musicbrainz.fdev.me` — возможный self-hosted endpoint, но
не default и не особая настройка приложения.

Для синхронизации используется полный список жанров MusicBrainz API
`/ws/2/genre/all?fmt=json&limit=100&offset=N`. Сохраняются стабильный MBID жанра
и его исходное каноническое имя. Отдельное читаемое английское имя автоматически
формируется для каждого жанра при загрузке всего каталога; ручное переименование
каждого элемента не требуется. Endpoint `fmt=txt` не подходит: он не содержит MBID.
Постраничная загрузка продолжается до получения полного каталога.

Запросы используют существующий HTTP governor MusicBrainz: публичный endpoint
подчиняется общей публичной очереди запросов, а self-hosted endpoint — только
настройкам throttling для self-hosted сервиса. Не следует навязывать публичный
gate self-hosted экземпляру.

## Загрузка и актуальность

- Первая загрузка запускается при Setup и не должна блокировать завершение Setup.
  Ошибка или отсутствие загруженного каталога отключает только выбор жанров; она
  не блокирует создание, редактирование или публикацию Local-записей.
- Каталог автоматически обновляется один раз в неделю. В Settings доступен
  явный запуск обновления и состояние/ошибка последнего запроса.
- Новая полная версия становится текущей атомарно. При ошибке загрузки сохраняется
  последний успешно загруженный каталог; частичный результат не публикуется.
- Каталог хранит только текущее состояние, не историю его версий. Обновление может
  заменить текущий набор и не меняет независимые metadata записей.

## Ввод и применение

- Жанры выбираются исключительно из загруженной библиотеки: multiselect с поиском
  и autocomplete. Свободное создание/ввод жанра запрещены.
- Это относится в том числе к постоянно видимой форме сведений артиста:
  единственная свободная строка «Жанр» не представляет целевой контракт.
  Полнота музыкальных полей описана в
  [`navidrome-metadata.md`](./navidrome-metadata.md); она не меняет scopes и не
  превращает generic tags в жанры.
- Читаемое английское имя из каталога одинаково применяется в UI, выборе,
  preview и `GENRE` публикуемых файлов независимо от RU/EN интерфейса.
  Сохраняются исходное имя и MBID.
  Это фактическое значение, а не CSS Title Case. Автоматическое оформление
  охватывает весь каталог, включая специальные написания/сокращения; оно не
  объединяет разные жанры и не меняет их смысл. Точная политика исключений не
  объявляется универсальным стандартом Spotify или другого сервиса.
- Жанры, уже присутствующие в модели MusicBrainz, сохраняют scope своих сущностей
  (artist, recording или release). Выбор эффективного файлового `GENRE`, включая
  fallback и явный пустой override, определяется разделом метаданных
  [`продуктового контракта`](./decisions.md#метаданные-и-управление).
  Проекция файлового тега не переписывает genres сущностей.
- Metadata публикации берутся только из MusicBrainz либо Local. MusicBrainz
  `genres` являются genre-источником; его общие `tags` не трактуются как genres.
  Произвольные исходные tags остаются evidence и никогда не используются как
  резервный источник жанров.
- Публикация канонического MusicBrainz-жанра не зависит от наличия локального
  каталога жанров. Для Local отсутствие каталога или пустой список genres
  допустимы при создании, редактировании и публикации.

## Границы

Не вводятся fuzzy mapping, синонимы, нормализация произвольных строк, миграция
старых данных, обратная совместимость, автоматическое назначение/распространение
жанров, merge/removal workflow или дополнительные политики для исчезнувших
жанров. При обновлении каталога существующие generic metadata не переписываются.
Автоматическое оформление загружаемых имён является исключением из запрета
нормализации: оно не разрешает fuzzy mapping произвольных старых значений.
Существующие публикации не переписываются молча:
действуют preview и явное подтверждение. Точечное ручное переименование упомянуто
как возможная будущая потребность; отдельный редактор/override lifecycle пока
не утверждены и не являются обязательным шагом загрузки.
Техническое размещение локального каталога в БД/кэше и API-контракт определяются
при реализации без предписания новых таблиц этим концептуальным документом.

## Представление metadata

Ссылка на жанр в metadata содержит `id` (MBID), `source_name` (исходное
каноническое имя) и `name` (читаемое английское имя). Выбор в редакторе передаёт
идентичность; для новых выбранных MBID сервер сохраняет имена из текущего
успешного каталога, не доверяя произвольным подписям клиента. Ссылки, уже
сохранённые у этого объекта, сохраняют свои серверные имена при изменении
остального списка и не переименовываются при обновлении каталога.
Проекция принятых MusicBrainz genres формирует читаемое имя
той же функцией и не требует предварительной загрузки каталога.

В metadata envelope для `genre` используются существующие состояния:
`value` — непустой список ссылок, `explicit_empty` — явное очищение,
`absent` — отсутствие override. Разрешение эффективного значения выполняется
на сервере до замораживания тегов publication attempt; worker не перечитывает
каталог для переименования уже подтверждённых тегов.

Readback принятых provider genres отделён от desired envelope: поле
`provider_genre_baseline` в metadata GET artist/release/recording представляет
только жанры той же связанной сущности текущего MusicBrainz source. Оно не
использует файловый fallback и не заполняет локальный draft. Отсутствие поля
означает отсутствие пригодного принятого значения; присутствующий пустой
`genres` означает принятое пустое provider-значение, не ручное очищение.
Evidence и digest относятся к этому readback, не служат PATCH precondition
или разрешением публикации. Mutation workflow сохраняет прежний desired-only
read и optimistic metadata revision.

## Внешний контракт

- [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API): полный список
  `/genre/all`, JSON и постраничная загрузка.
- [MusicBrainz Genre](https://musicbrainz.org/doc/Genre): жанры и произвольные
  пользовательские tags — не одно и то же.
- [Публичные ограничения](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)
  относятся к публичному сервису, не задают throttling self-hosted экземпляра.
