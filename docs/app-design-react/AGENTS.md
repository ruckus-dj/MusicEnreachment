# React design prototype

This is a separate design artifact, never part of the production frontend.
The owner explicitly authorizes a full graphical redesign of this React artifact,
prioritizing UI/UX and maximal appropriate use of React Aria Components. The live
`../app-design` remains a semantic and content reference, not a pixel-level limit.
Keep it intact; do not alter it as part of this work. Preserve existing behaviors,
fields, identities, data and approved product semantics. No screenshot artifacts.

Use React 19, TypeScript, Vite, Tailwind 4 and react-aria-components, matching the
application's libraries without editing `frontend/`. Test fixtures must retain
the original identities, source/publication distinction and approved semantics.

The current CatalogDemo is an incomplete migration scaffold. It is not the
graphical reference and does not demonstrate full parity. Avoid editing it unless
the owner explicitly expands the scope.

Format TypeScript files explicitly; do not format `original-fixtures.json`.
Its bytes are generated by `export-fixtures.mjs` and checked for drift. Fixture
tests must use actual exported titles/identities and scope repeated controls to
their object, not assume names or a single occurrence across editions.

All prototype styling must use Tailwind utilities in components or reusable
static utility strings. The owner permits one minimal Tailwind CSS entry with
Tailwind directives/configuration only; do not add handwritten CSS selectors,
component rules, `@apply` classes, CSS-in-JS, or runtime legacy-class translators.
Preserve the existing appearance, responsive behavior, theme switching and
React Aria interaction states when migrating styles.

Artist and release details are always-visible, text-like readonly fields, not
track-tag comparison tables. Edit enables the same fields in place; the fixed-size
Edit/Save action and reserved Cancel space must not shift the layout. Saving
updates prototype library state; Cancel/Escape discard the draft. Provider
identities remain readonly. Source files and existing publications are not changed
by editing object metadata; file/publication comparisons belong to a track.
