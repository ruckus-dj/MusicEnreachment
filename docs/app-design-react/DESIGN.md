# Визуальная система prototype

Текущие графические принципы самостоятельного React prototype. Продуктовые
правила задаёт [канонический контракт](../design/decisions.md#интерфейс); здесь
зафиксирована только визуальная подача.

## Характер и токены

Компактный музыкальный каталог и редактор назначений. Таблица и рабочее
содержимое важнее крупного hero; небольшие обложки, спокойный зелёный акцент,
тонкие границы и два уровня поверхности. Без тяжёлых теней, стекла и градиентных
героев. Декоративные цвета обложек не используются как статусы.

Системный sans-serif, tabular numbers для таблиц. Базовый ритм отступов —
4/6/8/12/16/20 px; main padding 12 px, gap панелей 10–12 px. Компактная кнопка
desktop 28–30 px, строка трека 36–42 px, строка с именем файла до 48 px;
заголовок таблицы 28 px, обложка строки 32 px, обложка шапки 64 px.

## Компоновка и адаптация

- Плотный desktop-first вариант при ширине от 1400 px — приоритет представления,
  а не условие завершения мобильной компоновки. В сопоставлении: кандидаты слева
  (около 240 px), список позиций в центре, доступные файлы справа (около 260 px);
  evidence и инспектор постоянно доступны в нижней части рабочей области;
  центральный список и боковые панели имеют собственную прокрутку. Высота
  inspector ограничена рабочей зоной, его содержимое при необходимости
  прокручивается без потери доступа к списку и действиям.
- На средней ширине панели складываются без чрезмерного сжатия содержимого;
  горизонтальная прокрутка, если нужна таблице, остаётся внутри её контейнера.
- На узкой ширине компоновка выбирается по сценарию: компактная навигация,
  подписанные строки или таблица с локальной прокруткой. Она не усложняет desktop;
  назначение файла доступно через выбор и действие, без обязательного drag-жеста.
- В shell боковая навигация и topbar остаются устойчивыми; прокручивается main.
  Инспектор не меняет ширину строк при выборе. Контекстное preview не скрывает
  последнюю строку.

## Основные паттерны

- **Compact header**: название, однострочное пояснение и действия без hero.
- **Каталог**: артистские карточки и плотные таблицы альбомов/треков; «Все» —
  начальное состояние фильтра.
- **Сопоставление**: кандидаты, track-list и файлы с отдельным inspector.
  Drop/keyboard feedback не резервирует пустую строку и не сдвигает таблицу;
  связанный источник визуально отделён от выбранного для публикации.
- **Metadata**: основные поля видимы сразу; дополнительные тематические группы
  стоят вертикальным стеком одной ширины в закрытом и открытом состоянии.
  Раскрытие сдвигает содержимое только вниз. Внутри группы допустима сетка.
- **Preview**: компактный список и постоянный inspector с «Поле / Сейчас / После»;
  на узком экране подробности доступны отдельной панелью с Escape и возвратом
  фокуса.
- **Settings**: разделы по типу задачи; действия рядом с выбором или сохранением,
  без лишней цепочки технических кнопок. Подтверждения показывают точное
  затрагиваемое содержимое. Текстовые поля имеют компактный явный Save и статус
  несохранённого ввода; autosave списков/переключателей не маскируется общей
  кнопкой Save. Ошибки и конфликты располагаются рядом с соответствующим вводом.

## Доступность и реализация

Использовать семантические buttons, labels, таблицы, radio и checkbox; видимый
focus outline 2 px; статус нельзя передавать только цветом. Drag-and-drop имеет
клавиатурный эквивалент. Учитывать `prefers-reduced-motion`; допустимы только
короткие переходы, не меняющие геометрию строк. Длинные имена и пути не теряют
смысл из-за обрезки.

Стили prototype используют Tailwind utilities в компонентах и статические
utility strings; не добавлять handwritten CSS selectors, `@apply` или CSS-in-JS.
Основные компоненты, fixtures и границы демонстрации описаны в
[`README.md`](README.md); ограничения проверки — в [`PARITY.md`](PARITY.md).
