# Отдельный React-прототип MeloTrove

По решению владельца от 2026-11-03 это единственный текущий графический
эталон. Стенд независим от приложения в `frontend/`. Тексты прежней
спецификации сохранены рядом (`01-product-and-flows.md`, `02-screens.md`,
`03-data-and-evidence.md`, `DESIGN.md`, `manual-release-proposal.md`); старый
runtime-макет удалён и не служит live reference. Продуктовые решения — в
[`../design/decisions.md`](../design/decisions.md).

Из корня репозитория:

- `task design:run` — отдельный Vite-сервер на порту 5175.
- `task design:check` — проверка fixtures, TypeScript, тесты и сборка только стенда.

Для изменений макета и документации по просьбе владельца не запускаются
проверки приложения и его CI.

Стек: React 19, TypeScript, Vite, Tailwind 4, React Aria Components;
TanStack Query включён в зависимости для асинхронных демонстрационных сценариев.
Зависимости и lockfile отдельные. Результат сборки — `build/design-prototype`,
не `build/frontend`; прототип не встраивается в сервер приложения.

`src/original-fixtures.json` — канонический самостоятельный набор демонстрационных
данных. Gate проверяет его структуру, уникальность identities, целостность ссылок
и сохранность критических известных identities; он не генерируется из удалённого
макета и не содержит выдуманного hash-provenance. Упрощение каталога происходит
только при отображении.

Проверка fixtures также охватывает данные ручного сопоставления, recovery и
ссылки Local-позиций на композиции. Регрессии проверяют как успешный исходный
набор, так и отказ при удалённом разделе или висячей ссылке; одна лишь проверка
верхнеуровневых identities не доказывает целостность набора.

Состояние переноса и известные отличия — в [PARITY.md](PARITY.md).
Не считать успешный gate доказательством полного визуального или сценарного
паритета. Проверка сценариев выполняется в живом интерфейсе без screenshot-артефактов.

## Уточнения текущей переработки

- Предпросмотр показывает точные отличия эффективных значений, включая очистку,
  обложку и lyrics. Невалидные metadata — «Невозможно обработать», отсутствие
  исходника и явное исключение — «Пропущено»; причины доступны по позиции.
- Измерения ReplayGain/R128 привязаны к конкретному аудио и доступны только для
  чтения. Отсутствие расчёта не блокирует публикацию. Автоматический расчёт,
  стандарт/алгоритм и состав альбомного аудиоконтекста ещё не спроектированы:
  демонстрационных вычислений и выдуманных результатов нет.
- Setup, инструменты, анализ источников и текущие операции моделируются в памяти.
  Демо-кнопки обозначают сценарий, а не успешный запрос к backend или проверку
  настоящей файловой системы. Канонические fixtures не подменяются новыми
  идентичностями или вымышленным происхождением.
- Входящие на узком экране представлены подписанными строками вместо широкой
  таблицы; desktop-first компоновка, плотность и оформление артиста сохранены.

Это описание поведения макета, не утверждение визуальной приёмки и не реализация
application/backend lifecycle. Продуктовые правила остаются в `../design/`.
