# 13. Основной интерфейс по утверждённому дизайну

Основание: запрос владельца привести приложение к `docs/app-design`, а не
маскировать пустую главную страницу. Это не быстрый косметический фикс:
отсутствуют оболочка и API основного каталога. Существующие анализ,
сопоставление и публикация переиспользуются, не переписываются.

Единственный графический эталон — интерактивный прототип
`docs/app-design/index.html` с его JS/CSS; `DESIGN.md` и `02-screens.md` содержат
письменное описание. Продуктовые ограничения — `docs/design`, они имеют приоритет
над графическим эталоном. Снимки удалены по решению владельца от 2026-11-01 и не
хранятся/перегенерируются на каждую правку. Демо-данные прототипа не переносятся.

## Выполнение — 8 коротких пунктов

Промежуточный статус 2026-10-29: каталог, ручное создание, маршруты и список
текущих публикаций реализованы; дополнительное отображение сохранённых
сведений проверено локальным `task verify` (445 frontend-тестов). План не
закрыт: повторная полная матрица CI, визуальная и сквозная приёмка остаются.
Дополнение на `1140cef`: стенд восстановлен, локальный релиз из 12 файлов
создан; первая позиция опубликована в прежнюю физическую output-папку,
проверена в CURRENT и каталоге. Исследуется зависшее отображение статуса
операции в открытой карточке; полная приёмка пока не завершена.
Свидетельства и ограничения — `../../reports/2026-10-29-library-interface-follow-up.md`.

- [ ] **Оболочка.** Перенести композицию прототипа: постоянные sidebar/topbar,
  компактные размеры, цвета и адаптивную навигацию: «Входящие / Медиатека /
  Источники / Операции / Настройки». Отдельную вкладку «Публикации» не добавлять;
  контроль публикаций и контекстный preview разместить в Медиатеке согласно
  решению 2026-11-01. Реализовать согласованные
  system/light/dark. Хранение согласовано владельцем 2026-10-28: `localStorage`
  отдельно для каждого браузера, при недоступности — в памяти до закрытия
  страницы; см. `docs/design/decisions.md`.
- [ ] **Каталог: данные.** Добавить чтение реальных артистов, альбомов и треков
  с поиском, фильтрами и ограниченной выдачей; отдельно вычислять source/audio
  availability и publication completeness по текущему контракту, не выдумывать
  unknown total/provider cache. Регенерировать клиент.
- [ ] **Медиатека.** Реализовать три представления прототипа: карточки артистов,
  таблицы всех альбомов и всех треков; открытие объектов, поиск, фильтр
  «В наличии / Не хватает / Все» без нового default, загрузку, ошибки и полезные
  пустые состояния. Для альбома показывать полный track-list независимо от
  match-filter; раздельно показывать source/audio/published показатели и
  текстовую completeness. Конкретные издания MusicBrainz показывать плоско и
  отдельно; missing entry объединять только по release-group identity, с явным
  выбором edition для просмотра и без unknown total как нуля. Контракт смешанных
  агрегатов остаётся открытым; см. `docs/design/decisions.md`.
- [ ] **Переходы и главная.** Убрать заглушку после мастера; связать медиатеку,
  артиста, релиз и позицию, прямые ссылки и возвраты в одну рабочую навигацию
  согласно прототипу. Ручное создание подключить к существующим возможностям,
  отсутствующий необходимый контракт реализовать, не оставлять мёртвых кнопок.
  Уточнение владельца 2026-10-28: до перехода к пустым входящим дать настроить
  источники. Форма создания релиза с нуля согласована владельцем 2026-10-28 по
  видимому дизайну `#create-release`; реализовать её в приложении как в дизайне,
  без добавления отсутствующих в форме возможностей (загрузка файлов, lyrics,
  обязательные поля) и с созданием отдельно от публикации. См.
  `docs/design/decisions.md`.
- [ ] **Рабочие экраны.** Привести источники, входящие, сопоставление и релиз
  к таблицам, панелям и плотности прототипа, сохранив действующие операции,
  доказательства, назначения и частичную публикацию.
- [ ] **Публикации, настройки и операции.** Встроить текущий publication path,
  snapshot, актуальность/attention и preview в контекст артиста/альбома/позиции;
  отдельную публикационную панель/sidebar не создавать. Выбор нескольких
  объектов даёт агрегированный preview с деталями до позиции; неизвестные файлы
  пропускать с причиной, не создавая collection entities/fallback. Сохранить
  текущие операции running/retry/error без завершённой истории и существующие
  downgrade/republish/authority guards. Основной индикатор «Метаданные
  изменились» отделить от completeness и строить по эффективным metadata
  относительно последней успешной CURRENT-публикации; baseline semantics,
  агрегат альбома и отдельность filesystem drift определены в решении владельца.
  Не выбирать незаданные алгоритм/hash/periodicity/color и не проектировать
  отдельную подсветку новых provider-значений защищённых полей без решения.
  Не менять bulk atomicity/cancel policy. Metadata update уже опубликованных
  artifacts — только после выбора объектов, preview и явного подтверждения;
  см. решение владельца от 2026-11-01 в `docs/design/decisions.md`.
  Настройки и текущие операции встроить в общую оболочку и навигацию;
  недостающее чтение добавить в API. Доступные действия должны работать с
  реальными данными; не добавлять декоративные неработающие элементы.
- [ ] **Сквозной пользовательский путь.** Проверить на стенде: завершение мастера
  → осмысленная пустая медиатека → добавление источника → анализ → входящие
  → сопоставление/публикация → обнаружение результата в каталоге.
- [ ] **Приёмка по дизайну.** Проверить реальный UI в браузере относительно
  интерактивного прототипа на desktop/mobile и в светлой/тёмной теме; проверить
  клавиатурное управление и отсутствие переполнения без сохранения screenshot-
  артефактов или матрицы снимков. Независимое ревью, полный `task verify`,
  обычные hooks, push и полный GitHub CI остаются обязательными. Не считать
  заглушку или один зелёный тест приёмкой.

Готовность: после настройки открывается настоящий рабочий интерфейс;
утверждённые разделы доступны из общей навигации, каталог читает реальные
данные, пользователь проходит путь без угадывания URL и обходных инструкций.
