# 14. Двухэтапное автоматическое сопоставление

**Статус: T01–T04 выполнены. T05 подключён для MusicBrainz без сведений об
исполнителе; подбор по исполнителю, Local fallback и перепубликация ещё не
подключены. T05 и T06 остаются открыты.**
[Исходный эксперимент](../../reports/plan14-matching-experiment.md) ·
[Прогон утверждённого алгоритма](../../reports/plan14-approved-layout-replay.md).

## Цель и границы

1. **Найти издания для всей группы.** По числу готовых файлов, названию альбома
   и исполнителю релиза отобрать ограниченный список. На этом этапе файлы
   позициям не назначаются.
2. **Сравнить целые раскладки.** Для каждого издания взять треклист, оценить
   пары «файл → позиция» и найти лучшее допустимое распределение всех готовых
   файлов. Сравнивать раскладки, а не максимальные оценки отдельных пар.
   Local и MusicBrainz используют один расчёт с разной подготовкой входных
   данных. Число готовых файлов — сигнал при поиске, а не предположение, что
   должны быть заняты все позиции издания.
3. **Применять только пригодный и актуальный результат.** Неполная раскладка
   или раскладка ниже порога ведут на ручной разбор. Равные пригодные
   результаты разрешаются стабильно. Автопубликация остаётся отдельным шагом
   со штатными условиями допуска; поиск, расчёт и предпросмотр сами её не
   запускают.

Действующие правила задаёт [продуктовый контракт](../../design/decisions.md#провайдеры-сопоставление-и-медиатека).
Порог `0.70` остаётся значением по умолчанию. План не меняет группировку,
защиту ручных связей и черновиков или политику публикации. Не считывать
и не переписывать теги исходных файлов ради подбора: использовать сохранённые
сведения анализа и действующие поправки кодировки по контракту.

## Этапы

- [x] **T01 — Воспроизводимый контроль.** Зафиксировать ревизию текущего
  алгоритма и сравнимый набор: «Punk-O-Мания 2» (21 файл, известное Local-издание
  из 21 позиции), сохранённый пример MusicBrainz и группы с неполными тегами.
  Снять текущих кандидатов, итог сопоставления и время этапов без записи связей.
  **Приёмка:** исходные и исправленные только в памяти теги проверяются
  раздельно; повтор на тех же входах даёт сравнимый результат. Контроль с
  исправленными тегами проверяет solver, а не качество поиска на исходных данных.
- [x] **T02 — Поиск кандидатов без назначений.** Сравнить текущий поиск с отбором
  по метаданным релиза для всей группы. Проверить неполные теги, сборники и
  издания с другим числом позиций; оценить размер списка и стоимость его
  подготовки. **Приёмка:** на неизменённом наборе показано, попало ли известное
  издание в список и на каком месте; если отсеялось — на каком шаге и почему.
  Получение списка не рассчитывает и не применяет назначения.
- [x] **T03 — Общий расчёт раскладки без применения.** Подготовить одинаковый
  вход для Local и MusicBrainz; сравнить лучшие допустимые раскладки при
  действующей политике. Замерить отдельно получение треклистов, оценку пар,
  распределение и полный путь; сравнить вычисление по запросу с повторным
  использованием оценок, не вводя предрасчёт всех пар по умолчанию.
  **Приёмка:** различимы полная раскладка, неполная раскладка, результат ниже
  порога и равные раскладки; перестановка входов не меняет результат.
- [x] **T04 — Согласовать правило выбора.** По результатам T01–T03 согласовать
  предел списка, критерий сравнения целых раскладок и два отдельных случая
  равенства: между изданиями и внутри одного издания. **Результат:** владелец
  утвердил top-10, один настраиваемый порог для каждой пары, полную раскладку
  с максимальной суммой и стабильный выбор при обеих ничьих. Правило внесено
   в действующий контракт.
- [x] **Исправления кодировки.** Показывать читаемые теги во «Входящих» и
  сопоставлении, сохранять однозначные поправки отдельно от оригинала и
  разрешать отмену. Для сомнительных поправок — просмотр «было → стало» и
   подтверждение для группы.
   - [x] Реализованы сохранение и отмена однозначных поправок, подтверждение
     неоднозначных вариантов «было → стало» и показ оригинала в инспекторе
     (`469746d8`). Поправки хранятся отдельно от исходных тегов.
   - [x] На изолированной группе проверены через API сохранение, повторное
     открытие и отмена. Исходные теги, состав группы и SHA-256 синтетического
     аудиофайла совпали до и после; группа «Punk-O-Мания 2» не редактировалась.
- [ ] **T05 — Подключить применение с проверкой актуальности.** После T04
  зафиксировать необходимые входы и ревизии группы, сохранённых сведений
  анализа, издания и политики; определить состав сохраняемых результатов для
  повторной доставки и разбора решения. Переиспользовать действующие проверки
  authority, подтверждения и допуска к публикации. **Приёмка:** устаревшее
  решение не применяется при изменении группы, издания или ручной authority;
  повторная доставка не дублирует связи; неполный результат не применяется
  частично. Local может применяться до восстановления MusicBrainz; при
  перепроверке только строго лучший пригодный результат для того же набора
  файлов запускает перепубликацию, в том числе без смены позиций. При переносе
  публикация проходит штатные условия допуска. По тому же пути успешная
  замена снимает прежнюю и регистрирует новую публикацию одной транзакцией;
  неудавшаяся повторяется отдельно. При смене пути снятие прежней публикации
  допускается только после полного успеха и повторной проверки защиты.
   - [x] Общий расчёт целой раскладки для Local и MusicBrainz, настраиваемый
     порог каждой пары и использование сохранённых поправок кодировки.
     На контрольном наборе при `0.70`: Local «Punk-O-Мания 2» — **21/21**,
     MusicBrainz «Жечь электричество!» — **52/52**. Это офлайн-прогон, не
     запись назначений и не публикация.
   - [x] **MusicBrainz без исполнителя** (`4ab5ae5c`): поиск хранит полный набор
     принятых изданий отдельно от top-10. Одно сохранённое решение определяет
     продолжение поиска и точные ID треков для применения. Неполная загрузка
     не считается доказанным отсутствием раскладки. Если поиск исчерпан,
     для ручного разбора отдельно загружаются оставшиеся издания только
     последнего этапа. Интеграционный тест проверяет этот путь на 11 изданиях.
   - [x] **Применение без исполнителя** (`4ab5ae5c`): перед записью проверяются
     группа, сохранённый анализ, поправки, порог, ручная защита и принятые
     ответы всех пройденных этапов. Изменение значимых данных провайдера
     блокирует применение; повторная доставка не дублирует работу.
     Повторное наблюдение неизменившейся общей записи не отменяет решение.
    - [x] **MusicBrainz с исполнителем** (`1da4a303`, `f9902e82`):
      ранжирование и применение используют сохранённые входы, порог,
      принятые ответы поиска, страницы каталога и полные треклисты.
      Интеграционный тест доводит результат до записи назначения; повторное
      наблюдение неизменившейся записи не блокирует применение.
    - [x] **Обновление открытого разбора** (`f5d548ad`): для MusicBrainz без исполнителя
      добавлен запрос переоценки при изменении принятого ответа, значимых данных
      треклиста или порога. Для разбора по исполнителю список изданий заново
      строится по принятым ответам из кэша. Подтверждённый пустой ответ
      обновляет только разбор. Неполный кэш не заменяет прежний разбор и
      не создаёт задачу применения.
    - [ ] **Local fallback**: расчёт, проверка актуальности каталога и атомарная
      запись с защитой точных исходников подготовлены. Сбой MusicBrainz,
      пустой результат и некорректный ответ различаются. Рабочая очередь ещё
      не применяет Local при сбое: подключение ждёт сквозного завершения
      перепроверки и перепубликации, чтобы не оставлять незакрытую защиту
      исходников.
  - [ ] Повторная проверка Local после восстановления MusicBrainz:
    сравнить точную сумму действующей раскладки Local с новой на тех же входах.
    При строгом выигрыше — дополнительные provider-связи или перенос
    автоматических назначений, перепубликация с приоритетом метаданных и
    барьер полного успеха перед снятием публикаций на других путях.
    Защита проверяется при допуске очистки и перед удалением, в том числе для
    другой позиции и пересекающихся корней. При подключении перепубликации
     связать её попытки с владельцем защиты: сброс выхода и отказ от попытки
     должны завершать или возвращать на перепроверку и эту обязанность.
      Сравнение с фактически применёнными назначениями Local реализовано
      (`7f873176`); независимая задача перепроверки и передача результата
      в публикацию ещё не подключены.
     После строгого выигрыша файлы без CURRENT не публикуются автоматически:
     первая публикация остаётся на ручном подтверждении.
- [ ] **T06 — Сквозная приёмка.** Сопоставить результаты с T01 на тех же входах;
  проверить ручной разбор, повторную доставку и защиту от устаревшего решения
  на изолированных данных. **Приёмка:** независимое ревью, штатные проверки
   приложения, отчёт с качеством отбора, временем и ограничениями. Группа
   «Punk-O-Мания 2» на рабочем стенде и исходные файлы остаются без изменений.
   Для уже подключённой ветки проверены точные назначения, отказ при
   устаревших данных, повторная доставка и полный ручной разбор. Оба коммита
   `4ab5ae5c` и `eb9dfefc` прошли `task verify`; на стенде `eb9dfefc` не
   изменились группа «Punk-O-Мания 2», её 21 файл и оценка. `/downloads` остался
    только для чтения. Повтор офлайн-контроля и проверки стенда для ветки
    с исполнителем описан в [промежуточном отчёте](../../reports/plan14-artist-verification.md).
    Сквозная приёмка Local и перепубликации не проводилась.
