# MeloTrove — локальный тестовый стенд (Go + Navidrome + Feishin)

Стенд поднимает полный контур проверки публикации: MeloTrove (backend + frontend в одном
контейнере), PostgreSQL, Navidrome (медиасервер) и Feishin (веб-клиент). Все порты
публикуются только на loopback.

## Сервисы и адреса

| Сервис | Адрес | Комментарий |
| --- | --- | --- |
| MeloTrove | http://127.0.0.1:8787 | UI приложения |
| Navidrome | http://127.0.0.1:4533 | медиасервер, музыка из `media-go` |
| Feishin | http://127.0.0.1:9180 | веб-клиент, сервер `stand` предзадан и заблокирован |
| PostgreSQL | внутри сети compose | db/user/password: `melotrove` |

Имя compose-проекта уникально — `melotrove-go-test-stand`, поэтому стенд не пересекается
с другими compose-проектами (`task run` использует `deploy/compose`).

## Требования

- Docker Engine с Compose v2
- Task (для команд `task stand:*`)

## Каталоги и данные

Все пути ниже указаны относительно `test_stand/`.

- `data/downloads/music` — входная музыка, монтируется в приложение **только для чтения**
  как `/data/sources/music`. Каталог должен существовать до первого `up`
  (`bind.create_host_path: false`), иначе запуск завершится ошибкой.
- `data/media-go` — выходная библиотека публикации, монтируется в приложение как
  `/var/lib/melotrove/output` (чтение/запись) и в Navidrome как `/music` (только чтение).
  Создаётся автоматически.
- `config/navidrome-go` — данные Navidrome (БД, кэш, обложки). Старый `config/navidrome`
  **не используется** и не изменяется.
- `appdata/` — зарезервированный локальный каталог стенда.
- Именованные тома `postgres-data` и `tools-data` — БД приложения и управляемые
  инструменты (ffmpeg/fpcalc).

Старые данные `test_stand/data/media` и `test_stand/config/navidrome` не монтируются в
новый стенд: они сохраняются на диске как есть и не затрагиваются.

## Команды

```bash
task stand:up     # сборка образа и запуск с ожиданием healthcheck (до 240 с)
task stand:logs   # логи всех сервисов (follow, последние 100 строк)
task stand:down   # остановка и удаление контейнеров/сети, БЕЗ удаления томов
```

`stand:down` не удаляет тома: база приложения и управляемые инструменты остаются между
запусками.

## Первичная настройка в UI

1. Откройте http://127.0.0.1:8787 и пройдите мастер первого запуска.
2. Инструменты: укажите каталог управляемых инструментов **внутри контейнера** —
   `/var/lib/melotrove/tools` — и скачайте выбранные релизы (ffmpeg, fpcalc).
   Пути хоста для приложения не подходят: оно видит только контейнерную файловую систему.
3. Источник: добавьте `/data/sources/music`. Этот каталог смонтирован только для чтения,
   поэтому очистка (cleanup) источника должна быть **выключена**.
4. Выходная библиотека: `/var/lib/melotrove/output` — сюда попадает результат публикации,
   этот же каталог Navidrome видит как `/music`.

Импорт не выполняется автоматически: новая база пуста, существующие файлы из старых
каталогов `data/media` и `config/navidrome` в стенд не попадают и не переносятся.

## Проверка публикации

1. Выполните публикацию в MeloTrove — результат появится в `test_stand/data/media-go`.
2. Откройте http://127.0.0.1:4533, при первом входе создайте пользователя Navidrome.
3. Запустите сканирование библиотеки Navidrome (после публикации — повторно).
4. Откройте http://127.0.0.1:9180 (Feishin): сервер `stand` уже настроен и заблокирован,
   войдите теми же логином и паролем, что и в Navidrome.

Feishin обращается к Navidrome по `http://127.0.0.1:4533`, то есть браузер пользователя
должен иметь доступ к этому адресу (стенд рассчитан на локальный запуск).
